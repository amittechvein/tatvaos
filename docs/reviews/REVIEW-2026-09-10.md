## What shipped

- **Hire and People are in the product catalogue.** Both appear as real products the
  system can grant, bill and allocate storage to — deliberately switched *off* for
  now, so nobody sees a greyed-out tile for something that does not exist yet.
- **A product can no longer switch itself off.** There was a bug where, the day you
  turned People on in the console, the next deploy would quietly turn it back off —
  and nothing would have told you. Fixed at the source, and written down.
- **A new tool that can catch that class of bug** (`verify-one-migration.py`): it
  tests a database change against a *running* system with real data, not just an
  empty one. The old checker could only ever see the empty case, which is exactly
  why this bug survived three green checks.
- **The phone app stays signed in properly.** Two simultaneous "refresh my session"
  calls used to sign the person out permanently. Now they share one call.
- **The phone app's server addresses live in one config file**, not six copies
  scattered across two files.
- **Screen sharing works from a real phone into a real meeting**, including the
  path where the person declines the permission.

## What I sent back

- **Mobile — `apps/mobile/lib/refusal.check.js` is not run by anything.** It is a
  good check, and it does the hard part right (it proves it can fail before you
  trust it passing). But `npm run check` runs jest, and this file is a plain script
  jest never picks up. So it runs only when somebody remembers. Wire it into `check`.
  *Why:* a check nobody runs has already stopped being a check.
- **Mobile — one unguarded keychain call in `api.js` (line 243).** The team just
  fixed exactly this shape on the *read* side; the *delete* side is still bare. It
  cannot hang the app any more (App.js catches it), so this is small — but if that
  delete throws, the phone retries a dead session on every single launch forever.
- **Core — did `verify-one-migration.py` actually get run with `--calibrate` on the
  Hire/People file?** The tool is honest enough to print "NOT calibrated" when it
  wasn't. I have no way to see the output. If it wasn't calibrated, one command
  closes it; if it was, say so in the commit and we are done.

Nothing else. The two files I read closest — the catalogue migration and the
migration checker — are the best-argued work I have reviewed here. Both explain
what hid the bug, not just what the bug was.
